# Workbench workflow

The main menu opens **UI Workbench**. Episodes and Editor are reserved screens with no editing functions yet. The Workbench currently has one implemented component: **Player Profile**. **Library** opens a second sidebar with the component card, design variants and editable layers. Click Library again or the drawer arrow to close it and enlarge the live preview. Themes (cyan), Motion FX (purple), Ambient FX (green), Reaction FX (red) and Event FX (amber) are shared resources: they use the full-width preview, with preset selection and editing together in the right inspector. Motion FX contains independent Entrance and Exit presets. Reaction FX controls momentary Pulse; Event FX controls XP gain and level-up feedback. The XP Bar is a mini component inside Player Profile, not a global category.

**Sound On/Off** in the top bar mutes or enables Workbench interaction cues immediately, including actions triggered by keyboard shortcuts. The setting is saved independently of the component. Audio for a future exported game component is not authored here yet.

## Preview and test

The **Preview & Test** panel below the live preview collects layout state, one-shot motion, playback, synthetic XP events and layout conditions. Select **Expanded** or **Compact** to hold the component in that layout. Ambient motion continues while the preview plays. **Enter**, **Exit** and **Pulse** are momentary previews; they return to the selected layout. **Pause preview** freezes the presentation clock and shader effects. **Reset test** restarts the preview and clears synthetic rewards.

Compact is a dedicated thin composition: player name, level and XP bar, without portrait or numeric XP readout. The Portrait + mask layer remains available to Expanded. Under **Library → Design**, use the variant selector to switch or rename a design, or duplicate it. Select a layer for contextual controls in the right panel; its On/Off control changes visibility. Variants share player data but keep their own portrait, layers, preset links and local values. Save component persists all designs.

The test buttons add synthetic XP events. **Near threshold** prepares a level crossing without changing the saved profile XP; **Clear rewards** removes preview events and that fixture. These events are not production progression and are not saved with the component. Select **XP Bar** from the Library layer stack to change the reusable progress drawing for this design; **Solo preview** isolates it while editing.

## Shared resource versus local override

1. Under Global Resources, choose Themes, Motion FX, Ambient FX, Reaction FX or Event FX. Select a preset in the right inspector to preview it immediately. Entrance and Exit selections replay their one-shot animations; Reaction triggers Pulse; Event triggers a synthetic XP gain; ambient and visual recipes appear in the live preview. This selection does not reassign the Player Profile's saved link. Adjust the grouped controls or type a numeric value; the controls scroll vertically. Editing creates a preview draft. Unsaved drafts stay with their presets while you browse; **Discard draft** reloads the saved values for the selected preset.
2. **Save** beside the preset name writes the resource and updates linked designs, except where they have local overrides. **Save as...** prepares a new name. **Delete** requires a second click, and refuses deletion while any design still links to the preset or if it is the category's last preset; replace those links first.
3. In the component inspector, use a linked-preset button in **Data & links** to assign a saved resource. It links immediately in memory; **Save component** commits that selection to disk. **Design overrides** changes values for this design only, leaving the global preset untouched. Changing a parameter marks it **Custom**; **Use preset** restores inheritance for that value, while the category button restores every value in that category.
4. **Save component** persists the shared base profile, all visual design variants, resource links and local overrides. It does not save unsaved UI Kit drafts or synthetic rewards. The header shows an asterisk while component changes are pending.

Undo/Redo covers in-memory parameter edits and resource operations represented by the edit snapshot. It does not undo writes already made to `UIKit.ini`, base data-field edits or synthetic XP events. **Reload** restores saved component state. A visual Appearance variant can change without altering Entrance or Exit.

Current ranges are visible alongside controls. Some signed speeds reverse movement below zero; nonnegative quantities such as glow and density can exceed the normal intensity but cannot be negative. The current presentation offers eight entrance and eight exit algorithms, two authored frame variants, separate ambient-module speeds, six editable Theme color slots and independent XP-event composition. It is not an arbitrary motion-keyframe editor or freeform geometry editor.
